# eBay SEO 돋보기

AI에게 "좋은 eBay 제목 써줘"라고 하면 일반적인 기준으로 그럴듯한 제목이 나온다. 이 스킬은 그 대신 **현실에서 이미 채점된 데이터(답안지)**로 무엇이 판매를 가르는지 찾고, 그 **딱 하나(핵심 변수)**에 힘을 모은다. 세 단계는 순서대로 한다. 앞 단계가 다음 단계의 기준이 되기 때문이다.

```
1. 상위 목표   무엇을 위해 하는가  → 성공 기준을 정한다
2. 답안지      팔린 것 vs 안 팔린 것 → 표로 정리하고 숫자로 비교한다 (스크립트)
3. 핵심 변수   둘을 가르는 딱 하나  → 고르고, 실행 방법과 제목으로 바꾼다
```

## 1. 상위 목표

사용자가 상위 목표를 이미 말했거나 프로젝트 문서(PRD 등)에 있으면 그대로 쓰고, 없으면 묻지 말고 아래 기본값을 쓴다. 분석을 시작하기 전에 묻는 질문이 많으면 사용자가 지친다.

- 기본 상위 목표: **적은 시간으로, 재고를 쌓지 않고, 지속적으로 판매한다**
- 그래서 성공 기준은 노출이나 조회수가 아니라 **판매(Sold)**다. 많이 보였지만 안 팔린 리스팅은 실패로 본다.

이 목표를 보고서 맨 위에 한 줄로 적는다. 나중에 핵심 변수를 고를 때 "이 변수를 바꾸면 이 목표에 가까워지는가"를 기준으로 쓴다.

## 2. 답안지

### 입력 받기

같은 상품(같은 검색어)의 **완료된 리스팅**이 필요하다. 팔린 것만 있으면 무엇이 판매를 가르는지 알 수 없다. 안 팔린 것과 비교해야 차이가 보인다.

- 사용자가 아직 데이터를 주지 않았다면 이렇게 안내한다: eBay에서 상품을 검색한 뒤 필터에서 **Completed items(완료된 리스팅)**만 켜고 **Sold items는 켜지 않는다.** 그래야 팔린 것과 안 팔린 것이 함께 나온다. 결과 페이지를 전체 선택해 복사한 텍스트를 붙여넣거나, `title, price, shipping, status` 열이 있는 CSV를 준다.
- eBay 페이지를 직접 긁어 오지 않는다. 약관 문제가 있고, 사용자가 붙여넣은 데이터로 충분하다.

### 표로 정리하고 비교하기

붙여넣은 내용을 파일로 저장한 뒤 번들 스크립트를 실행한다. 직접 세지 말고 스크립트를 쓰는 이유는, 같은 입력에 매번 같은 숫자가 나와야 결론을 믿을 수 있기 때문이다.

```bash
python <이 스킬 경로>/scripts/analyze_listings.py 입력파일.txt --json 결과.json
```

스크립트가 하는 일:
- 리스팅마다 제목, 가격, 배송비, 팔림/안 팔림, 위치, 가격 제안 여부를 뽑는다
- 조건별(무료 배송, 한국 발송, 가격 제안, 총액이 중앙값 이하 등) 판매율을 비교한다
- 제목 키워드별로 "들어간 리스팅의 판매율 - 빠진 리스팅의 판매율"을 계산한다
- 표본이 작으면(팔림이나 안 팔림이 5개 미만) 경고한다

**스크립트가 인식하지 못한 줄이 많거나 리스팅을 하나도 못 찾으면**, eBay 화면 형식이 예상과 다른 것이다. 원본 텍스트를 직접 읽고 리스팅마다 제목, 가격, 배송, 팔림/안 팔림을 표로 만든 뒤 CSV로 저장해서 스크립트를 다시 돌린다. 무엇을 보고 팔림/안 팔림을 판단했는지 보고서에 적는다.

## 3. 핵심 변수

스크립트의 숫자는 후보일 뿐이다. 여기서부터가 판단이다. **차이가 가장 큰 숫자를 그대로 고르지 않는다.** 아래 네 가지를 모두 통과하는 것 중 가장 강한 하나를 고른다.

1. **차이가 크고 표본이 받쳐 준다.** 판매율 차이가 크더라도 그 조건을 가진 리스팅이 2~3개뿐이면 우연일 수 있다.
2. **다른 요인으로 설명되지 않는다.** 예를 들어 "무료 배송"의 판매율이 높아도, 무료 배송 리스팅이 전부 더 싸다면 진짜 변수는 총액일 수 있다. 가격, 상태(새것/중고), 판매 형식이 한쪽에 몰려 있지 않은지 리스팅 목록에서 확인한다.
3. **판매자가 바꿀 수 있다.** "판매자 평점이 높다"는 당장 바꿀 수 없다. 제목 단어, 배송 조건, 가격 제안, 구성품 명시처럼 다음 리스팅에서 바로 바꿀 수 있는 것이어야 한다.
4. **구체적이다.** "제목을 잘 쓴다"가 아니라 "제목 앞쪽에 'with photocard'를 넣는다"처럼, 읽자마자 그대로 실행할 수 있어야 한다.

후보가 비슷해서 하나를 고르기 어렵다면 두 가지 질문을 던져 본다.
- **목표를 10배로 키우면?** 이 상품을 지금보다 10배 팔아야 한다면 어떤 변수 하나에 걸겠는가.
- **시간을 1/10로 줄이면?** 다음 리스팅을 5분 안에 올려야 한다면 무엇 하나만 챙기겠는가.

어떤 후보도 네 가지를 통과하지 못하면, 억지로 고르지 말고 "이 답안지로는 핵심 변수를 확정할 수 없다"고 쓰고 무엇을 더 모아야 하는지 적는다. 틀린 확신보다 정직한 보류가 낫다.

## 4. 제목과 실행 방법

핵심 변수가 제목과 관련 있으면 제목을 2~3개 제안한다. `references/ebay-title-rules.md`의 규칙과 점검표를 읽고 따른다. 특히 80자 제한을 반드시 지키고, 제목에 넣는 키워드는 **답안지의 팔린 리스팅에 실제로 나온 단어**에서 가져온다. 상품에 없는 특징은 넣지 않는다.

핵심 변수가 제목이 아니면(배송 조건, 가격 제안 등), 그 변수를 다음 리스팅에 어떻게 적용할지 구체적으로 쓰고, 제목은 기본 규칙만 지킨 안 하나만 제안한다.

## 보고서 형식

보고서는 항상 이 구조로 쓴다. 사용자가 다음 리스팅을 올리기 전에 위에서부터 읽고 바로 행동할 수 있게 하려는 것이다.

```markdown
# [상품명] eBay 돋보기 분석

**상위 목표:** (한 줄)

## 답안지
- 리스팅 N개 = 팔림 A개 + 안 팔림 B개 (판매율 X%)
- (표본이 작으면 경고 한 줄)
- 가격 중앙값: 팔림 $ / 안 팔림 $

## 핵심 변수
**(딱 하나, 구체적으로)**
- 근거: (그 조건이 있을 때와 없을 때의 판매율과 개수)
- 다른 요인으로 설명되지 않는 이유: (한두 줄)

## 다음 리스팅에서 할 일
1. (바로 실행할 수 있는 행동)
2. 제목 제안 (글자 수 표시)
   - `...` (NN자)

## 버린 후보
- (후보) : (왜 핵심 변수가 아닌지 한 줄)

## 이 분석의 한계
- (표본 크기, 데이터 수집 시점, 확인 못 한 요인)
```

## 개인 정보

답안지에는 다른 셀러의 리스팅이 들어 있다. 보고서에는 판매자 아이디를 적지 않는다. 사용자가 자기 판매 실적을 함께 주더라도, 사용자가 공개해도 된다고 하지 않는 한 공개 저장소에 올라갈 파일에는 적지 않는다.
